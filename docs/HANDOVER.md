# Передача проекта · AI-консультант Астана-РЭК

Памятка для разработчика, который принимает проект. Что за документы лежат в репозитории,
что в них внутри и как ими пользоваться.

Проект: интерактивный вертикальный тач-киоск (экран 1080×1920) с AI-консультантом для клиентов
АО «Астана-РЭК». Сейчас готов фронтенд-демо: работает без бэкенда на встроенных моках и базе знаний
с сайта astrec.kz. Бэкенд и подключение оборудования — следующий этап.

Репозиторий (приватный): https://github.com/rsolutions-immersive/AREK-Asist

---

## Быстрый старт

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

Прямые ссылки на экраны: `#/` (заставка), `#/assistant`, `#/documents/connection-private-house`, `#/account`.
Тестовые данные — в `docs/DEMO_GUIDE.md`.

## Документы проекта — в каком порядке читать

### 1. `README.md` — начать отсюда

Главная техническая инструкция.

Внутри: текущее состояние, возможности, стек (React 19, Vite 8, TypeScript 7), запуск, переменные `.env`,
архитектура, API для бэкенда (пути и форматы), база знаний, ролики заставки, печать и протокол
Device Bridge (связь с датчиком и принтерами), запуск Chromium на киоске, требования к персональным данным.

Как использовать: прочитать первым — этого достаточно, чтобы запустить проект и понять, куда подключать бэкенд.

### 2. `docs/BUSINESS_AND_ARCHITECTURE.md` — зачем и для кого

Внутри: заказчик и контекст, исходные требования и их трактовка, пользователи, бизнес-процессы
(ожидание → консультация → документы и печать чека → лицевой счёт), целевая архитектура, черновик API,
безопасность, ключевые факты из базы знаний, открытые вопросы к заказчику, журнал решений с датами.

Как использовать: читать, чтобы понять бизнес-логику. Новые договорённости с заказчиком —
дописывать в «Журнал решений», нерешённое — в «Открытые вопросы».

### 3. `docs/PROJECT_STRUCTURE.md` — карта файлов

Внутри: дерево проекта и таблица — какой файл за что отвечает (экраны, API, моки, база знаний,
печать, голос, стили, словари языков).

Как использовать: искать здесь, где что лежит. При добавлении, переносе или удалении файлов — обновлять.

### 4. `TODO.md` — задачи

Внутри: только задачи и статусы, по этапам. Статусы: `[ ]` новая, `[~]` в работе, `[x]` готово,
`[-]` отменена (с причиной). Номера сквозные (T-001, T-002, …) и не переиспользуются.
Этапы 1–2.6 выполнены. Этап 3 «Интеграция» (T-020…T-024) ждёт исполнителя:
реальный API бэкенда, агент оборудования, реальные справочники и вычитка казахского, QR на чеке,
тест на настоящем киоске.

Как использовать: брать задачи отсюда; новую задачу заводить сюда до начала работы.

### 5. `AI_HISTORY.md` — журнал выполненной работы

Внутри: по каждому действию — время, автор, что сделано, какие файлы добавлены, изменены или удалены,
как проверить, риски. Сгруппирован по этапам из TODO, сверху самое новое. Здесь же отчёт
технического аудита фронтенда (этап 2.3, задача T-033) со списком известных дефектов.

Как использовать: смотреть, почему код сейчас такой. После своей работы — дописывать запись
(формат описан в `AGENTS.md`).

### 6. `docs/DEMO_GUIDE.md` — памятка для показа

Внутри: ссылки на все экраны, тестовые данные (ИИН, номера для сценариев «счёт не найден» и «сбой биллинга»,
флаги ошибки принтера и сбоя интерфейса), вопросы для консультанта, сценарий показа на 5–7 минут,
что в демо реальное, а что выдумано.

Как использовать: для демонстрации заказчику и быстрой ручной проверки после изменений.

### 7. `AGENTS.md` — правила для ИИ-ассистентов (Claude, Codex, Cursor)

Внутри: обязательный порядок работы — прочитать документы, сверить запрос с TODO, записать новую
бизнес-информацию, сделать задачу, записать отчёт в AI_HISTORY, обновить карту файлов.
Форматы TODO и журнала, правила качества: факты о компании брать из `data/knowledge/`,
ничего не выдумывать, маскировать персональные данные.

Как использовать: ИИ-ассистенты читают его сами. Если работаете без ИИ — тот же порядок полезен и человеку.

### 8. `CLAUDE.md`

Одна строка: подключает `AGENTS.md` для Claude Code. Трогать не нужно.

## Известные проблемы (из аудита T-033, см. AI_HISTORY.md)

Для демо не мешают, но до подключения реального биллинга их нужно исправить:

1. Если сессия сбросилась по таймауту, пока консультант «думает», его ответ может попасть
   к следующему посетителю.
2. ИИН, БИН и телефон при вводе видны на экране полностью, хотя правила проекта обещают маскировку.

Менее срочно: нет автотестов, линтера и CI; часть кнопок меньше проектных 88 px; ответы бэкенда
не проверяются во время работы; в рабочем режиме отказ микрофона подменяется демо-анимацией.
